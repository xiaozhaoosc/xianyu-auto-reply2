## 二、问题诊断与修复时间线

### 阶段1：滑块验证体系修复（08-21）

**背景**：自动滑块失败率100%（Baxia 响应码300），人工等待模式在服务器上无法操作。

| 问题 | 根因 | 修复 |
|------|------|------|
| 自动滑动必败 | Patchright 强制走 CDP `Input.dispatchTouchEvent` 触摸事件，闲鱼 PC 滑块(#nc_1_n1z)是鼠标驱动 | `slider_stealth.py` 删除触摸分支，统一真实 mouse 轨迹，`has_touch=False` |
| 人工等待无窗口 | headless=True 无界面 | 发现服务器有显示器：`DISPLAY=:10` 可用（X10 socket 属 ken4zhao），start_all.sh 加 `export DISPLAY="${DISPLAY:-:10}"`，slider_args 的 headless 改回 False |
| 人工通知只发邮件 | 通知渠道未接入 | 新增 `_send_slider_manual_notification` 同步函数，读账号绑定的飞书/邮箱/钉钉渠道发送 |

**新增功能**：
- 纯手动模式 `captcha.slider_mode=manual`：跳过自动滑动直接等人工
- `captcha.manual_wait_seconds`（默认120秒）：人工等待窗口
- `notify.token_expiry_notify` 开关：Token正常过期是否通知（默认关）
- 前端 Settings.tsx / SliderModeSetting.tsx 对应配置项

### 阶段2：Token 生命周期梳理与保留旧 Token（08-23）

**用户反馈**：周五周六滑块能过，周日下午开始自动+人工都失败。

**关键修复——滑块验证失败不再清除旧 Token**：

```python
# cookie_token_manager.py 原1335-1347行
# 修改前：
self.current_token = None
await self._delete_cached_token()
return None
# 修改后：
logger.warning("滑块验证失败，保留原有token继续使用")
return self.current_token   # 失败也返回旧token，账号不中断
```

异常分支同样处理。**效果**：验证失败期间旧token继续服务直至自然过期。

**Token 有效期机制**（代码分析结论）：

| 参数 | 值 | 说明 |
|------|-----|------|
| Token 缓存 TTL | 6~15小时随机 | `random_token_cache_expiry()`: 5~10h基础+1~5s~h偏移 |
| TOKEN_REFRESH_INTERVAL | **82800秒=23小时**（本会话从72000改来） | start_all.sh:13 |
| cookie_refresh_interval | 180秒 | WebSocket侧Cookie刷新轮询 |

### 阶段6：账号离线重大故障排查（08-24）

**现象**：账号离线，登录续期任务显示"正常"但无监听。

**根因**：
```
websocket/.env:38  AUTO_START_WEBSOCKET=false   ← 调试遗留开关！
```
WebSocket 服务启动时跳过 CookieManager.start()（_bootstrap.py:102），`total_instances: 0`。

**修复**：
1. `AUTO_START_WEBSOCKET=true` + 重启 → 账号恢复在线
2. 数据库 `xy_scheduled_tasks`: cookies_refresh interval 600 → **3600**（代码默认值被DB覆盖，之前改代码无效的教训）

**教训**：服务"看起来正常但账号全离线"时先查 `.env` 开关；改代码默认值前先查数据库已有配置。

### 阶段7：COOKIES续期周期深度优化（08-24）

**发现两层频率控制**，真正元凶不在轮询间隔：

```python
# cookies_refresh_task.py:101 _build_success_expire_at
# 修改前：续期成功后60~300秒即再次"到期" → 实际每天24次浏览器会话
# 修改后：
return now + timedelta(seconds=random.randint(3 * 3600, 5 * 3600))  # 3~5小时随机
```

理由：在线账号由 WebSocket心跳/mtop响应 set-cookie 自动滚动续期，浏览器续期仅作离线保活兜底；3~5小时随机消除模式化访问特征。

### 阶段8：续期日志断档补齐（08-24）

**现象**：websocket.log 只到"Playwright启动成功"无下文。
**排查**：数据库表 `xy_scheduled_cookies_refresh_log` 记录正常（5268条全success），断档仅在 websocket 端过程日志。
**修复**（cookies_refresh_service.py）补齐5类节点日志：注入数量、导航开始、modal检测失败(WARNING)、Cookie为空(WARNING)、续期成功(INFO含数量)。

## 四、项目对比：xianyu-super-butler 分析结论

（clone 因网络失败，通过 webfetch 抓取源码分析）

| 维度 | 本项目 | super-butler |
|------|--------|--------------|
| 数据库 | MySQL 异步 | SQLite 同步 |
| 架构 | 4服务分离 | 单进程 Start.py |
| AI回复 | 外接 | 内置议价引擎+免费中转 |
| 买家互动 | 自动评价 | +收货致谢+求小红花+买家信用查询 |
| 订单 | 基础 | 历史订单一键拉回+真实成交金额 |
| 滑块 | 需人工兜底 | 声称99%（有头浏览器） |
| IP代理 | ✅ **每账号独立代理**(proxy_type/host/port/user/pass) | ❌ 无 |

**IP代理结论**：本项目已支持 socks5/http 代理（xy_account 表字段），Clash Verge 7891端口可用；合租7-8人同出口IP风险高，建议3+账号配独立代理。
